## Working rules

1. Keep observations, interpretations, proposed changes and test results distinct. Cite external sources directly and preserve contrary evidence.
2. Use the selected GSD workflow for each issue's feature setup, with a separate feature branch and linked worktree. Record setup as pending until that workflow has run.
3. Include runnable code examples and their verification instructions when they exist. Link only to actual code and executed notebooks; distinguish synthetic tests from live Hermes behavior.
4. Exclude credentials, private task contents, full transcripts and machine-specific paths. Review all staged public content before pushing.
5. Keep each change scoped. Check Markdown links and whitespace before committing; run tests appropriate to any code change. Merge completed work into `main` with a merge commit and clean only its verified, merged worktree and branch. Active feature worktrees remain open while their work is pending.
