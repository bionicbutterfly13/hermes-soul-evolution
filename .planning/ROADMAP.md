# Roadmap: Hermes Soul Evolution

## Overview

Six issue streams turn the [dated baseline](../docs/baseline-001.md) into runnable synthetic examples, reviewable evidence protocols and Quill-authored posts. The core value is an executive operator with observable initiative, verified follow-through and continuity across sessions. This roadmap uses standard granularity for a documentation and experiment project. It does not introduce an MVP application, UI or database skeleton.

**Recorded:** 2026-09-07. Research was recorded on 6 September 2026; the local audit was compiled on 7 September at 09:40 America/New_York. The baseline concerns one installation, with operator-reported observations that have not been independently reproduced. F01 remains positive evidence of identity loading in one recorded session, not a seventh repair stream.

**Current authority:** Planning only. Creating this roadmap does not run examples, diagnose or repair Hermes, change services or active SOUL instructions, invoke providers, draft blogs or publish them. The outcomes below describe future acceptance, not completed work. Every requirement remains pending.

## Phases

Integer phases identify the six planned issue streams. Decimal phases are reserved for later authorized insertions.

- [ ] **Phase 1: F02 Scheduler startup evidence** - Distinguish registration, execution, accepted output and visible startup failure.
- [ ] **Phase 2: F03 Routine freshness** - Establish current routine evidence and single scheduling ownership.
- [ ] **Phase 3: F04 Bounded overnight work and reflection** - Demonstrate finite synthetic execution and source-linked reflection, with a gated live trial protocol.
- [ ] **Phase 4: F05 Memory continuity** - Demonstrate correction-aware synthetic recall and separate the live continuity evidence layers.
- [ ] **Phase 5: F06 Specialist artifact acceptance** - Distinguish transported results from artifacts that satisfy acceptance and review requirements.
- [ ] **Phase 6: F07 Continuity and runtime comparison** - Select observable continuity behaviors and define the actual three-condition comparison.

**Goal**: Readers and Dr. Mani can distinguish historical routine success from present operation and identify one responsible scheduling path per routine.

**Requirements**: F03-01, F03-02, F03-03

### Phase 3: F04 Bounded overnight work and reflection

**Goal**: Readers can inspect bounded synthetic task execution and evidence-linked reflection, while Dr. Mani can assess the prerequisites for a later integrated overnight trial.
**Depends on**: No other phase for public examples or protocol preparation. Future live trials require Phase 1 F02 scheduling, Phase 4 F05 memory and Phase 5 F06 artifact acceptance evidence.

  3. Dr. Mani can review an overnight trial protocol that records one assigned task and finite limits before execution, requires F02/F05/F06 evidence, and withholds an integrated live success claim when any prerequisite or acceptance result is missing. (F04-03)
  4. Readers can access Quill's F04 issue post citing the 7 September preparation-only baseline, tested execution and reflection examples, actual decisions and remaining limits. It does not equate startup recovery or a preparation report with overnight execution. (F04-04)
